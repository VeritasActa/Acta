    How verification works

    1. The receipt payload is serialized using JCS canonicalization (RFC 8785)
    2. The canonical bytes are verified against the Ed25519 signature (RFC 8032)
    3. The public key in the receipt is the only trust anchor: no certificate authority, no API
    4. If the signature checks out, the receipt has not been modified since signing

    What this verifier does NOT do

    • Does not verify the signer's identity, only that the signature is valid
    • Does not check revocation status
    • Does not contact any server
    • Does not verify the receipt's claims are true, only that they haven't been tampered with

    Verify from the command line

    npx @veritasacta/verify receipt.json
